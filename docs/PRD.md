# PRD: AI 녹음 요약 서비스

## 1. 문서 정보

- 제품명: 가칭 `Summary`
- 문서 버전: v0.1
- 작성일: 2026-06-02
- 우선 출시 형태: Android 모바일 앱
- 확장 후보: Web 앱, Mac/PC 오디오 녹음, 외부 회의 서비스 연동

## 2. 제품 개요

`Summary`는 사용자가 회의, 대화, 인터뷰, 강의 등을 녹음하면 음성을 텍스트로 변환하고, 변환된 내용을 목적에 맞는 구조화된 요약 결과로 정리해주는 서비스다.

초기 버전은 Android 앱에서 휴대폰 내장 마이크를 이용해 주변 음성을 녹음하고, 서버에서 음성 인식 및 AI 요약을 수행한 뒤 앱에서 결과를 확인하는 흐름을 목표로 한다.

## 3. 문제 정의

사용자는 회의나 긴 대화 이후 중요한 내용을 다시 정리하는 데 많은 시간을 쓴다. 특히 다음과 같은 문제가 있다.

- 긴 대화에서 핵심 내용을 빠르게 찾기 어렵다.
- 회의록, 할 일, 결정 사항을 수작업으로 정리해야 한다.
- 녹음 파일은 있지만 다시 듣는 데 시간이 오래 걸린다.
- 대화 내용이 길수록 주제별 정리, 요점 추출, 후속 액션 관리가 어렵다.

## 4. 목표

### 4.1 제품 목표

- 사용자가 모바일 앱에서 쉽게 녹음할 수 있다.
- 녹음 파일을 텍스트로 변환할 수 있다.
- 변환된 텍스트를 회의록, 요약, 액션 아이템 등 유의미한 형태로 정리할 수 있다.
- 사용자가 결과물을 확인, 수정, 저장, 공유할 수 있다.

### 4.2 MVP 목표

- Android 앱에서 마이크 녹음 기능 제공
- 녹음 파일 목록 및 상세 화면 제공
- 녹음 파일 업로드 및 처리 상태 표시
- 음성-텍스트 변환 결과 제공
- 회의록 형식 요약 제공
- 핵심 요약, 결정 사항, 할 일, 주제별 정리 제공

## 5. 비목표

MVP에서는 아래 기능을 제외한다.

- 전화 통화 자동 녹음
- 다른 앱의 내부 오디오 직접 녹음
- Zoom, Google Meet, Teams 실시간 봇 참여
- 실시간 자막 생성
- 여러 사용자의 공동 편집
- 화자 식별 고도화
- 기업용 관리자 콘솔

## 6. 대상 사용자

### 6.1 1차 사용자

- 회의 내용을 자주 정리해야 하는 직장인
- 인터뷰나 상담 내용을 기록해야 하는 사용자
- 강의, 세미나, 미팅 내용을 정리하고 싶은 사용자
- 개인 대화나 아이디어 회의를 기록하고 싶은 사용자

### 6.2 주요 사용 시나리오

1. 사용자는 회의 전에 앱을 실행하고 녹음을 시작한다.
2. 회의가 끝나면 녹음을 종료한다.
3. 앱은 녹음 파일을 서버에 업로드한다.
4. 서버는 음성을 텍스트로 변환한다.
5. 서버는 텍스트를 분석해 회의록 형식으로 요약한다.
6. 사용자는 앱에서 결과를 확인하고 필요한 부분을 수정한다.
7. 사용자는 요약 결과를 복사하거나 공유한다.

## 7. 핵심 사용자 흐름

```text
앱 실행
  -> 녹음 시작
  -> 녹음 중 상태 확인
  -> 녹음 종료
  -> 파일 저장
  -> 서버 업로드
  -> 텍스트 변환
  -> 요약 생성
  -> 결과 확인
  -> 수정/공유/저장
```

## 8. 기능 요구사항

### 8.1 Android 녹음

- 사용자는 앱에서 녹음을 시작할 수 있어야 한다.
- 앱은 Android `RECORD_AUDIO` 권한을 요청해야 한다.
- 녹음 중에는 명확한 녹음 상태를 표시해야 한다.
- 사용자는 녹음을 일시정지, 재개, 종료할 수 있어야 한다.
- 녹음 파일은 로컬에 임시 저장되어야 한다.
- 네트워크가 불안정해도 녹음 파일이 유실되지 않아야 한다.

### 8.2 녹음 파일 관리

- 사용자는 녹음 파일 목록을 볼 수 있어야 한다.
- 각 녹음에는 제목, 생성일, 길이, 처리 상태가 표시되어야 한다.
- 사용자는 녹음 제목을 수정할 수 있어야 한다.
- 사용자는 녹음 파일을 삭제할 수 있어야 한다.
- 삭제 시 서버에 저장된 음성 파일과 텍스트 결과도 삭제 대상에 포함되어야 한다.

### 8.3 업로드 및 처리 상태

- 앱은 녹음 종료 후 사용자의 확인을 받아 서버에 업로드할 수 있어야 한다.
- 업로드 진행률을 표시해야 한다.
- 서버 처리 상태를 표시해야 한다.

처리 상태 예시:

- `로컬 저장됨`
- `업로드 중`
- `텍스트 변환 중`
- `요약 생성 중`
- `완료`
- `실패`

### 8.4 음성-텍스트 변환

- 서버는 업로드된 음성 파일을 텍스트로 변환해야 한다.
- 긴 파일은 안정적으로 처리할 수 있어야 한다.
- 변환 결과는 원문 텍스트로 저장되어야 한다.
- 가능하면 문단 단위로 구분된 결과를 제공해야 한다.
- MVP에서는 화자 식별을 필수로 하지 않는다.

### 8.5 요약 생성

사용자는 다음 형식의 요약 결과를 받을 수 있어야 한다.

#### 회의록 형식

- 회의 제목
- 회의 일시
- 핵심 요약
- 논의 주제
- 결정 사항
- 할 일
- 이슈 및 리스크
- 다음 회의에서 확인할 내용

#### 긴 대화 분석 형식

- 전체 요약
- 핵심 포인트
- 주제별 정리
- 감정 또는 분위기 메모
- 중요한 발언 또는 주장
- 후속 조치

### 8.6 결과 편집 및 공유

- 사용자는 생성된 요약 결과를 수정할 수 있어야 한다.
- 사용자는 텍스트 결과를 복사할 수 있어야 한다.
- 사용자는 요약 결과를 공유할 수 있어야 한다.
- MVP 공유 방식은 일반 텍스트 공유를 우선한다.

## 9. 웹 앱 고려사항

웹 앱에서도 브라우저 권한을 통해 Mac 내장 마이크를 사용할 수 있다. 사용자가 브라우저에서 마이크 접근을 허용하면 기본 입력 장치로 녹음할 수 있다.

다만 Mac에서 재생되는 전체 시스템 오디오는 일반 웹 앱만으로 직접 녹음하기 어렵다. 시스템 오디오 녹음이 필요할 경우 다음 옵션을 고려한다.

- 사용자가 가상 오디오 장치 설치
- 데스크톱 앱 개발
- 회의 서비스의 녹화/녹음 파일 업로드
- 브라우저 탭 공유 기반 오디오 캡처

MVP에서는 웹 앱을 필수 범위로 두지 않고, Android 앱 출시 이후 확장 후보로 둔다.

## 10. 권한, 개인정보, 법적 고려사항

- 앱은 녹음 전에 사용자에게 녹음 목적과 저장 방식을 안내해야 한다.
- 사용자는 녹음 중임을 명확히 인지할 수 있어야 한다.
- 대화 녹음은 지역과 상황에 따라 참석자 동의가 필요할 수 있다.
- 앱 내에 녹음 동의 안내 문구를 제공해야 한다.
- 사용자는 자신의 녹음 파일과 변환 텍스트를 삭제할 수 있어야 한다.
- 서버 저장 데이터는 암호화 저장을 고려해야 한다.
- 외부 AI API를 사용할 경우 데이터 전송 범위를 명확히 고지해야 한다.

## 11. 비기능 요구사항

### 11.1 성능

- 1시간 이하 녹음 파일을 안정적으로 업로드할 수 있어야 한다.
- 업로드 실패 시 재시도할 수 있어야 한다.
- 처리 완료 후 사용자에게 상태 변경을 알려야 한다.

### 11.2 안정성

- 녹음 중 앱이 백그라운드로 이동해도 녹음이 유지되어야 한다.
- 네트워크 오류가 발생해도 로컬 파일은 유지되어야 한다.
- 서버 처리 실패 시 재처리할 수 있어야 한다.

### 11.3 보안

- API 통신은 HTTPS를 사용해야 한다.
- 사용자별 데이터 접근 권한을 분리해야 한다.
- 음성 파일, 텍스트, 요약 결과는 사용자 본인만 접근할 수 있어야 한다.

## 15. MVP 출시 기준

MVP는 아래 조건을 만족하면 출시 가능한 상태로 본다.

- Android 앱에서 마이크 녹음이 가능하다.
- 녹음 파일이 로컬에 저장된다.
- 녹음 파일을 서버로 업로드할 수 있다.
- 서버에서 텍스트 변환이 가능하다.
- 서버에서 회의록 형태의 요약을 생성할 수 있다.
- 앱에서 원문 텍스트와 요약 결과를 확인할 수 있다.
- 사용자가 결과를 복사하거나 공유할 수 있다.
- 사용자가 녹음 및 결과물을 삭제할 수 있다.

## 17. 주요 리스크

- Android에서 장시간 백그라운드 녹음 안정성 확보 필요
- 기기 내부 오디오 녹음은 OS 제한이 커서 MVP 범위에 부적합
- 음성 인식 비용이 사용량에 따라 빠르게 증가할 수 있음
- 긴 녹음 파일 처리 시간이 사용자 경험에 영향을 줄 수 있음
- 개인정보 및 대화 녹음 관련 법적 안내가 필요함
